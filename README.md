# Вместе ♡

Мобильное PWA для двух людей: 100 встроенных идей, собственные предложения, игры, взаимные симпатии и совместные планы. Статические HTML/CSS/JS без сборки и собственного backend.

## Запуск

```sh
npm ci
npm start
```

Откройте http://127.0.0.1:4173. Можно использовать любой статический HTTP-сервер. Открытие `index.html` через `file://` не поддерживает ES modules, PWA и соединение.

Для публикации достаточно загрузить `index.html`, `manifest.json`, `service-worker.js`, `.nojekyll`, каталоги `css`, `js`, `data`, `assets`, `vendor` в корень репозитория. Settings → Pages → Deploy from a branch → main → `/ (root)`. Все пути относительные, поэтому приложение работает и в подкаталоге GitHub Pages. HTTPS нужен для установки, буфера обмена и service worker.

## Как пользоваться

1. Укажите имя и создайте комнату.
2. Отправьте ссылку второму человеку. Для обмена изменениями откройте её одновременно.
3. Добавляйте идеи, ставьте сердечки. Две симпатии от разных участников создают матч.
4. Добавляйте идеи «В план», меняйте порядок за ручку или стрелками, сохраняйте вечера.
5. В карточках «20 вопросов», «Правда или действие», «Что бы ты выбрал?», «Кто скорее?» доступны игровые карточки.
6. В профиле можно изменить имя и значок, создавать задания, экспортировать и импортировать резервную копию.

На iPhone: Safari → Поделиться → На экран Домой. На Android: меню браузера → Установить приложение. Локальные ресурсы, шрифт, иллюстрации и PeerJS входят в офлайн-кэш после первого успешного открытия.

## Данные и связь

- IndexedDB: `ideas`, `reactions`, `plans`, `customTasks`, `users`, `meta`. Отдельная база на локальный профиль; каждая запись привязана к комнате.
- UUID комнаты создаётся с помощью `crypto.randomUUID`; ссылка является секретом доступа. Не публикуйте её в открытом доступе.
- [PeerJS 1.5.5](https://peerjs.com/client/getting-started) подключён локально. Служба PeerJS Cloud используется только для сигнализации. Данные комнаты передаются через канал WebRTC, серверной базы нет.
- Из SHA-256 room ID выводятся слоты A/B. Первый занимает A, второй B и соединяется с A. Есть повторные попытки после смены сети, возврата в приложение и обновления. Одновременно подключаются не более двух устройств.
- Обмен метаданными (ID, время, версия, автор изменения, короткий контрольный хеш), затем только отличающимися записями. Хеш служит для выявления различий, не для криптографической проверки. Повторный приём идемпотентен, входящие записи не пересылаются обратно автоматически.
- Конфликты: last-write-wins по `updatedAt`, затем `version`, `writerId`, содержимому. Локальные часы логически монотонны, но это MVP, не полноценный CRDT. Удаление сохраняется как `deletedAt`.
- Пустая база получает все отсутствующие записи через тот же обмен метаданными — это полный snapshot, разбитый на пакеты. После очистки браузера можно выбрать собственный прежний профиль в разделе «О связи и приватности», чтобы вернуть авторство и реакции.
- Нельзя гарантировать прямое соединение во всех сетях: строгий NAT, корпоративные ограничения и недоступность сигнализации могут мешать. Собственный TURN/сервер не используется. При проблемах смените сеть или передайте JSON-копию. Офлайн-работа не зависит от связи; синхронизации, когда оба закрыли приложение, нет.
- Удаление локальной копии не удаляет данные партнёра. Полное удаление данных браузера лишает его локальной базы; восстановление возможно из второй копии или JSON. Регулярно экспортируйте данные.
- Нет аналитики, рекламы, удалённых шрифтов или внешнего API идей. PeerJS signaling видит технические сведения соединения.

## Проверка двух вкладок

Для обычного использования вкладки одного браузера принадлежат одному человеку. Для имитации второго телефона откройте приглашение во второй вкладке с дополнительным `&participant=2`: она получит отдельный постоянный профиль и отдельную базу. Приглашения, скопированные приложением, не содержат этот параметр. Ещё надёжнее использовать разные профили браузера или инкогнито.

## Разработка и тесты

```sh
npm test
# При запущенном npm start:
npm run test:browser
node tests/recovery.mjs
```

Playwright использует Chromium (`npx playwright install chromium`, если браузер ещё не установлен). Основные тесты — без сети; браузерные проверки соединения требуют доступа к PeerJS Cloud. Результаты и снимки сохраняются в игнорируемый `test-results/`.

- `data/ideas.js`: коллекция и метаданные; `data/games.js`: вопросы и задания.
- `js/db.js`, `store.js`, `sync.js`, `peer.js`: хранение и обмен.
- `js/screens.js`, `ui.js`, `app.js`, `plans.js`: экраны, взаимодействия и сборка вечера.
- `css/styles.css`: токены, компоненты, адаптивность и reduced motion.
- `scripts/assets.mjs`: исходники локальных SVG; `scripts/finish-assets.mjs`: копирование шрифта и формирование списка кэша.

При изменении списка файлов выполните `node scripts/finish-assets.mjs`. Для выпуска новой версии увеличьте версию кэша в этом скрипте и заново сгенерируйте service worker. Новый worker активируется после закрытия старых вкладок, чтобы не смешивать версии модулей.

Шрифт Nunito распространяется по OFL, лицензия в `assets/NUNITO-LICENSE`; PeerJS — MIT, лицензия в `vendor/PEERJS-LICENSE`. Все иллюстрации — локальные SVG, написанные для проекта; пользовательские экраны-референсы в сайт не включены.

## Проверено

Chromium: создание комнаты, две вкладки с разными участниками и реальным PeerJS, двусторонние изменения, общий матч, reconnect, офлайн-перезагрузка, резервная копия, планы и игры; ширины 360/390/450/1280. Отдельные проверки удаления, восстановления пустого устройства и возврата прежнего профиля. Физические iPhone/Android и установка через системное меню требуют проверки на устройствах.
